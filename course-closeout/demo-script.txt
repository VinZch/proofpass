ProofPass 课程展台讲稿（3 分钟，含随机问答）
整理日期：2026-11-07。以下是排练用讲稿，不是团队已经完成现场展示的记录。

一、上场前准备

1. 本组按课程要求为 3 人；下面只有“讲解／操作／答问”三个轮换职责，不代填成员姓名，也不预设谁已完成了哪些工作。每个人都要能操作文件指纹、指出报告日期和解释技术边界。
2. 将整个交付目录复制到演示电脑。双击 ProofPass_跨校证书核验实验室.html，打开“03 · 文件指纹”。提前用页面按钮下载“虚构证书_原版.txt”和“虚构证书_改动一个标点.txt”。两个文件均为虚构样例，现场不使用真实学生材料。
3. 另一标签预先打开主网页“06 · 实测证据”。需要联网只读复核时，先在项目目录运行 npm run serve，再访问 http://127.0.0.1:8080/upgrade/。本轮演示不连接钱包，不签发、批准、执行或撤销，不依赖现场发交易。
4. 准备三份升级版包：evidence/upgrade-sepolia-original-package.json、evidence/upgrade-sepolia-corrected-package.json、evidence/upgrade-sepolia-key2-package.json。实测证据栏目可直接下载相应包和报告。
5. 联网方案先检查 RPC 可读；断网方案保留本地图片、报告及日志。主 HTML 的文件指纹功能可独立运行；实测截图栏目需随附 evidence/ 和共享展示文件。8081/upgrade/ 是临时本机 EVM，不能当作 Sepolia 演示。

二、3 分钟时间轴

00:00—00:15｜问题与范围
动作：展示项目标题，不进入钱包。
讲：“我们研究竞赛与技能证书跨校核验。原型把三件事分开：内容有没有变、链上记录是什么状态、学校是否认可。痛点频率和实际节省时间还要靠真实访谈与测量，不能由演示直接推出。”

00:15—00:50｜必做档：现场计算文件指纹
动作：在“03 · 文件指纹”两框先选同一原版文件，指出两份 SHA-256 相同；第二框换成改动一个标点的文件，指出指纹不符和计算时间。
讲：“这是浏览器本地读取字节、计算 SHA-256，没有上传文件，也没有上链。相同字节得到相同摘要；改动一个标点会改变摘要。但重存或重新扫描也可能改变字节，所以哈希不一致不能单独证明证书造假。这里显示的时间是本机时间，不是区块链时间戳。”

00:50—01:25｜进阶档：真实测试网证据
动作：切换“06 · 实测证据”，依次点原始版本、更正版、新密钥凭证；指出查询时间、区块号和报告下载入口。
讲：“另一部分使用 Sepolia 公共测试网。这三张是已经保存的真实技术查询截图：原版被更正版替代，更正版被紧急撤销，新密钥签发的另一张仍有效。三份内容都匹配，但状态不同。机构停用限制后续操作，不会自动撤销所有历史凭证。现在展示的是报告标注区块的历史结果。”
可选：网络已预检且操作熟练时，用 10 秒在升级页导入 key2 包并点“读取链上状态”，展示新查询日期；若等待或报错，立即转回已保存报告，不能把历史结果说成刚查到的最新状态。

01:25—01:45｜治理与真实边界
动作：指出证据栏目中的准入、轮换、停用、紧急撤销交易与只读检查说明。
讲：“升级版采用三个治理账户中两个批准的规则，已经实际测试准入、原子更正、轮换、停用和紧急撤销。这三个账户都在同一本机钱包，证明的是代码权限规则，不证明三家机构已经共同治理；独立浏览器也仍使用同一 RPC 提供商。”

01:45—02:00｜结论与未完成部分
讲：“上链保存的是承诺和状态，不自动证明获奖事实或持有人身份，学校也仍要独立审批。现有官方渠道或中心化方案足够时，不必增加区块链。真实访谈、团队现场材料和成员实际分工由我们自行补齐；网页中的模拟工时与访谈不作研究结论。”

02:00—03:00｜教师随机点两名非组长成员答问
操作成员停止切页；被点成员按下列题库选择相关回答，每题约 20—30 秒。不要由组长代答。若教师提前提问，省去可选联网查询，先回应问题。

三、随机成员题库（排练参考，不是已完成问答记录）

Q1：文件哈希到底证明什么？改文件名会影响吗？
A：它比较文件字节。只改文件名而内容相同，摘要不变；重新保存导致字节改变时摘要可能不同。它不能证明签发机构、获奖事实或持有人是谁。

Q2：哪一段真正上链，哪一段只是离线教学？
A：主网页的文件指纹、会话签名和本地日志是离线教学；Sepolia 合约交易才是实际公共测试网操作。主网页“实测证据”嵌入的是已保存的链上结果，点开图片不会发送交易。8080/upgrade/ 按固定配置读取 Sepolia；8081 是本机临时链。

Q3：证书显示“有效”，为什么学校仍未审批？
A：有效是技术状态，表示这条记录在查询时点没有被撤销、替代或过期等。内容是否对应真实事实、出示者是否本人、是否满足学校规则，要另行核实。当前持有人挑战与现实身份绑定未完成。

Q4：为什么不直接做中心化数据库？
A：中心化签名登记可以完成很多相同功能。只有存在真实多方共同治理需求、各方愿意承担成本且比较证据支持时，才有进一步采用链的理由。我们还没有三后端实测对照，48 条记录是公式生成的模拟参数，不能证明效率提升。

Q5：机构停用了，为什么新密钥凭证仍有效？
A：停用禁止该机构当前密钥继续签发、普通撤销或更正，不自动修改旧记录。紧急撤销只针对指定凭证；这里更正版被撤销，而另一张 epoch=2 凭证没有被撤销，所以仍可技术通过。

Q6：密钥轮换是否让旧凭证失效？
A：机构编号保持不变，当前签发密钥与 epoch 改变；旧密钥不能再签发，但旧记录保留原签发地址和密钥版本。是否有效还要看该凭证自己的更正、撤销和有效期状态，不能只看旧密钥已退役。

Q7：三账户两票是不是三家独立机构？
A：不是。本次用同一本机 MetaMask 的三个账户做权限测试。正式多方治理还需要独立保管密钥、机构资质审核、责任和争议处理协议；这些不能由地址数量代替。

Q8：为什么断网不直接显示之前的“有效”？
A：旧报告只证明旧查询时点。读不到可信当前状态就应该显示无法确认或待复核。现场可以解释历史报告，但不能把缓存当最新状态，查询不到也不能直接判定造假。

Q9：篡改凭证包会怎样？
A：固定协议对结构化字段规范化，并把随机盐、网络、合约和签发上下文纳入承诺；改标题或盐后重新计算的承诺与链上记录不匹配。这里核验的是解析后的规定字段，不是 JSON 文件排版字节；字段顺序变化不应误判。

Q10：今天的自动测试证明全部完成了吗？
A：没有。本轮只运行 offline.test.mjs 与 protocol.test.mjs，4 组通过，覆盖离线状态逻辑和基础版 v2 协议等。它不代替浏览器现场文件选择、真实访谈、全部合约测试、公共网最新查询或课程完整验收。

Q11：课程要求三十行以内合约，升级版为什么更长？
A：进阶基础档提交 ProofPassRegistry.sol，现有源文件 29 行，承担授权、登记、读取和撤销。ProofPassGoverned.sol 是另附的治理扩展，不能把它冒称为三十行基础档，也不应靠把代码挤成一行满足限制。

Q12：AI 做了什么，你们做了什么？
A：AI 已参与代码、测试、文档和证据整理；本轮测试网交易最终确认由用户操作。每位成员只说明自己实际执行和复核的工作，并展示对应记录。真实访谈、成员现场取证及现场问答由团队亲自完成，不能用 AI 生成脚本代替。

四、断网或故障时的替代流程

• 外网断开但本地浏览器正常：完整演示“同文件匹配→一标点改动不匹配”；随后打开本地实测截图与报告，明确说“这是 2026-11-07 保存的历史技术证据，当前未重新联网查询”。
• RPC 超时或拒绝：保留错误或待复核提示，不反复点钱包，不修改网络地址绕成其它链；用已保存报告说明状态时点与失败关闭原则。
• localhost 服务未启动：双击主 HTML 先做课程必做档；截图与 JSON 可直接用本地查看器打开。不要为现场救场新增部署或发送交易。
• 展示电脑缺少随附图片目录：只展示仍能运行的单 HTML 文件指纹实验；用备用电脑或完整目录展示报告，不把缺图界面当成功运行。
• 文件选择或浏览器失败：切换事先验证的备用浏览器；若仍失败，坦诚记录不能现场运行的步骤，不能用旧截图声称本次已完成操作。
