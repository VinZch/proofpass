ProofPass 课程结项：必须由团队亲自补齐的清单
整理日期：2026-11-07。用户已明确成员信息和真实访谈自行填写；本清单不生成受访者、姓名、实际工时或成员贡献。
方框保持未勾选。只有团队提交相应真实材料后，才能填写完成日期、责任人与证据路径。

一、真实访谈与问题证据

[ ] 按课程指南至少访谈 3 位真实利益相关方，覆盖管理者、使用者、被影响者各一；说明其实际职责和与本场景的关系，不能仅按职称套角色。
[ ] 逐次记录日期、地点/形式、时长、匿名编号、身份说明、参与同意及录音同意；没有同意录音时仅做文字纪要。原话与团队解释分开，附能支撑结论的位置。
[ ] 根据真实操作画出现状流程图，标出查询入口、信息断点、责任方、补件/询证和认定节点。没有跨校经历的访谈明确标“非跨校”，不能当跨校痛点的直接证据。
[ ] 实际操作时间与等待时间分列；注明来自日志、现场测量还是受访者估计，保留数量、分母和相反案例。没有数据的项写“未取得”，不以模拟数值填充。
[ ] 对照申报书中的更大招募计划，列出“计划数／实际数／缺少角色／对结论的限制”，不能把计划 6—8 人等当已完成样本。
[ ] 核对签发方证据：申报书拟访谈签发机构，已有 C 类提纲主要问带队/指导教师。教师经历不能自动证明其有正式发证或撤销权。补访签发/证书管理岗位；若无法接触，明确机构准入和责任流程仍是假设。
[ ] 按实际同意范围保管材料，纪要移除无关个人信息。遵守申报书已经写出的录音/匿名记录保存期限；不要将真实证书原文、证件号、联系方式或未经同意的原话放进公开网页或链上。

团队填写：实际访谈人数____；三类角色覆盖____；匿名材料位置____；仍缺证据____。

二、团队自行操作的现场材料与链上取证

[ ] 拍摄本校真实现场照片或系统截图，记录日期、地点、页面用途和取得授权；不要用模拟图片、外校素材或 AI 图像冒充本校现场。
[ ] 团队在展示电脑亲自打开单 HTML：两次选择同一文件显示相同指纹，再改一个标点显示不同指纹，保留现场画面与时间。浏览器本地时间不是链上时间戳。
[ ] 团队亲自使用升级页只读导入 TEST ONLY 包并查询，保存含查询日期、网络、合约、区块号和结论的截图及报告；复核原版被替代、更正版紧急撤销、epoch=2 包状态。若网络失败，记录失败，不把旧结果当最新。
[ ] 原始证据截图不重绘结果，不裁掉决定结论的日期/网络/区块；标注截图操作者及截图来源。可以另做排版副本，但应保留原图与对应报告。
[ ] 已有 IAB 技术截图和只读复核确属真实测试成果，可作为技术附件；课程指南要求团队自取的现场与链上截图，仍须成员亲自补齐，不能把 AI 操作记录改署名为成员现场操作。
[ ] 需要展会使用历史截图时，在图注写明保存日期和“历史查询结果”；本次网页集成 QA 图只是排版与交互检查，不新增链上业务证据。
[ ] 本轮展台只做离线实验与只读查询，不为补截图重复部署或发钱包交易。若以后确需重新做写交易，遵守课程仅测试网、免费测试币、无真实资产钱包的要求，并单独保留真实过程。

团队填写：文件指纹现场操作者____；链上只读取证操作者____；日期____；照片/截图/报告位置____。

三、3 名成员的实际工作与随机答问

[ ] 按课程“3 人一组”填写真实成员信息。simulation-research/ 中 4 个虚构排练角色不代表实际组员，也不是成员工作量证明。
[ ] 每人记录自己实际承担的需求、操作、修改、验证、取证或报告工作，以及日期和可复查产物；没有参与的内容不记为独立完成。
[ ] 实际投入若记录工时，说明记录来源。模拟计划小时、48 条对照模型及自动测试持续时间都不能充当成员劳动工时。
[ ] 每位成员独立演示文件指纹，解释“哈希／签名／链上状态／持有人／校内认定”五者的区别，并能指出一个尚未解决的问题。
[ ] 用 demo-script.txt 题库随机抽人排练，尤其非组长成员。教师约停留 3 分钟、提两个问题，不要安排只有组长会讲或代答。
[ ] 说明中期到终稿的变化：基础离线实验、基础 Sepolia 合约、治理升级及真实技术证据接入分别何时完成、由谁操作和复核。

建议每人亲自填写一行：姓名____；实际工作____；日期____；文件/操作证据____；能独立解释的代码段____。

四、一页 AI 使用说明与人工自查

[ ] 列实际使用的 AI/检索工具及用途，不凭印象写“全部由我们独立编写”，也不把未使用的工具列入。
[ ] 保存有代表性的关键提示词、AI 生成部分、人工修改部分、修改原因及复核方式，结合具体文件或功能，不只写“用于润色”。
[ ] 说明本项目 AI 已协助代码、测试、文档和模拟材料；用户亲自点击过钱包最终确认。每位成员实际做了什么仍需本人核对填写。
[ ] 明确所有研究模拟内容：16 条核心预设案例、8 条扩展设计场景、15 段虚构访谈、48 条三方案参数记录、模拟角色和计划工时。它们用于排练和方法展示，不是已开展的真实研究结果。
[ ] 真实测试结果另列：本轮指定 offline/protocol 两份文件合计 4 组通过；此前 Sepolia 交易、固定块 RPC 审计及独立浏览器报告各有证据。不要把 4 组测试写成 4 笔链上交易、完整系统验收或田野调查。
[ ] 人工核对错误边界：没有持有人身份绑定或学校正式审批；同钱包三个账户不等于三家机构；同一 PublicNode RPC 不等于多提供商共识验证；只读 eth_call 拒绝不是失败实发交易；哈希匹配不证明现实事实。
[ ] 不使用“上链后无法造假”“已经实现跨校互认”“性能提升百分之多少”等超出证据的结论；如提性能数据，应给真实数据来源、比较口径、分母和限制。
[ ] 课程要求不可由 AI 代替的内容均由团队实际完成：真实访谈、本校现场材料、含日期链上取证、展会现场问答。AI 使用说明本身也由成员核对签认。
