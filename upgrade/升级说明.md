## 新增能力

| 能力 | 行为与限制 |
|---|---|
| 稳定机构编号 | `(institutionId, credentialId)` 标识记录。机构换钱包后编号不变；每张凭证仍保存实际签发地址和当时的密钥版本。 |
| 2/3 阈值治理 | 部署时指定三个不同治理地址，固定两票。准入、轮换、启停、紧急撤销均需提案和两位成员批准，再独立执行；创建者计一票。不是通用多签钱包。 |
| 密钥轮换 | 新密钥负责同机构后续操作，也可撤销或更正该机构旧记录；旧密钥不能继续写入，且永不复用。旧凭证历史不会被改写。 |
| 原子更正 | 一笔交易同时撤销旧证书、登记新 ID、写入双向版本关联。任一步失败全部回退；已替代记录不能再次分叉更正。 |
| 紧急撤销 | 即使机构停用，治理成员仍能以两票撤销指定凭证，记录原因摘要和时间。不会批量撤销整个机构。 |
| 独立核验与追溯 | v3 包绑定链、合约、机构、签发密钥版本和前版编号。可跨浏览器导入、核验、下载报告，沿前后版逐条查询。 |

普通撤销、更正仍需机构当前有效密钥。停用限制后续写入，不自动否定该机构全部历史证书；必须根据调查结果逐张紧急撤销。密钥轮换不会自动解除停用。

## 合约和协议边界

- 三个治理地址和 2/3 阈值部署后固定，不提供治理成员自身的轮换。任一治理成员可否决未执行提案，优先防误操作；恶意否决或两个治理密钥同时失去控制会影响可用性。这不是生产治理方案或安全审计通过声明。
- 提案最长 7 天、同一地址只计一票；执行、否决、过期后不能重用。准入、轮换、启停、紧急撤销每次执行都会增加机构 revision，使该机构其他旧提案失效，需要重新提出。普通签发不改变 revision。
- 页面给提案设置 24 小时有效期。提案原因只上链 SHA-256 摘要；原始依据需线下留存。原因输入应使用虚构非敏感内容，摘要不是加密。
- 承诺为 `SHA256(UTF8("ProofPass:v3:") || salt32 || UTF8(canonical(payload)))`，沿用受限 JSON 排序编码。payload 的固定字段见 `upgrade/protocol.js`；v2 包拒绝由升级入口导入，继续在基础版核验。
- 链上只存承诺、地址、时间和关联；标题及持有人代号不上链。持有人挑战、防重放身份绑定、正式学校审批、自动更正通知及公平性能实测尚未实现。
- 核验报告是查询区块快照；页面 60 秒后要求重查。读取记录固定区块并复核哈希，RPC 错误或过旧区块不显示成功。服务依赖可信 RPC，不是轻客户端。
- 交易进入钱包后没有审批超时重发；包在发起交易前保留为草稿，失败或等待不表示已登记。发生广播后超时，应先核对交易哈希及链上状态，不直接重复发送。
